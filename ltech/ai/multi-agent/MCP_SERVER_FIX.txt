🔴 CRITICAL ISSUE:

Problem: Cold start (new session) returns empty data
  - User pilih: u1566482_leontech
  - Query result: "Data tidak ditemukan" ❌
  - Meskipun log menunjukkan schema benar

Root Cause: MCP server tidak membaca PGSCHEMA environment variable
  - Environment variable di-set: PGSCHEMA=u1566482_leontech
  - MCP server tetap pakai default: prive,public
  - Search_path tidak ter-update per request

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 SOLUTION:

Modified custom MCP server (/var/www/ltech/scripts/mcp-server.mjs)
to DYNAMICALLY read PGSCHEMA and SET search_path before each query!

Key Changes:
1. Added getCurrentSchemas() function
2. Set search_path BEFORE each query execution
3. Log schema being used for debugging

🔧 CODE CHANGES:

File: /var/www/ltech/scripts/mcp-server.mjs

Added function:
```javascript
function getCurrentSchemas() {
    const pgschema = process.env.PGSCHEMA;
    const schema = process.env.SCHEMA;
    const schemasStr = pgschema || schema || "prive,public";
    const schemas = schemasStr.split(",").map(s => s.trim());
    console.error(`[MCP] Current schemas: ${schemas.join(", ")}`);
    return schemas;
}
```

Modified query handler:
```javascript
case "query": {
    const client = await pool.connect();
    try {
        // Get current schemas and set search_path
        const currentSchemas = getCurrentSchemas();
        const searchPath = currentSchemas.join(", ");
        
        console.error(`[MCP] Setting search_path to: ${searchPath}`);
        await client.query(`SET search_path TO ${searchPath}`);
        
        // Then execute query
        await client.query('BEGIN READ ONLY');
        const result = await client.query(sql);
        await client.query('COMMIT');
        
        return { content: [{ type: "text", text: JSON.stringify(result.rows) }] };
    } finally {
        client.release();
    }
}
```
