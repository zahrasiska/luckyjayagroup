🔴 CRITICAL ISSUE:

Problem: Saldo kas dan perhitungan finansial SALAH
  Query: "Tampilkan saldo kas"
  AI Result: -85.254.128.740,74 (WRONG)
  DB Result: -64.484.018.550,74 (CORRECT)
  
Root Cause: NULL values dalam operasi matematika!
  100 - NULL = NULL ❌
  SUM(debit - kredit) with NULL = INCORRECT ❌

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 THE PROBLEM:

SQL Arithmetic + NULL = DISASTER:
- debit = 100, kredit = NULL
- 100 - NULL = NULL (NOT 100!)
- SUM ignores NULL, but arithmetic doesn't
- Result: COMPLETELY WRONG financial reports

Example:
```sql
-- ❌ WRONG (produces incorrect totals):
SUM(j.debit - j.kredit)

-- If data:
-- Row 1: debit=1000, kredit=500  → 500
-- Row 2: debit=2000, kredit=NULL → NULL (lost!)
-- Row 3: debit=1500, kredit=800  → 700
-- SUM = 1200 (should be 2200!)
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔧 SOLUTION:

Added MANDATORY COALESCE rule to CORE_MEMORY:

**ALWAYS USE COALESCE FOR ARITHMETIC:**
```sql
-- ✅ CORRECT (NULL-safe):
SUM(COALESCE(j.debit, 0) - COALESCE(j.kredit, 0))
SUM(COALESCE(d.qty, 0) * COALESCE(d.harga, 0))
SUM(COALESCE(t.total, 0) - COALESCE(t.bayar, 0))
```

📊 CORRECT SQL EXAMPLES:

Saldo Kas:
```sql
SELECT 
    SUM(COALESCE(j.debit, 0) - COALESCE(j.kredit, 0)) as saldo
FROM j
JOIN prive.rekening r ON j.rek = r.kode
WHERE r.nosubklasifikasi IN (110, 120);
```

Laba:
```sql
SELECT 
    SUM(COALESCE(d.total, 0) 
        - (COALESCE(d.hpp, 0) * COALESCE(d.qty, 0)) 
        - COALESCE(d.diskon, 0)
    ) as laba
FROM d;
```

Piutang:
```sql
SELECT 
    SUM(COALESCE(t.nilaitotal, 0) - COALESCE(t.bayar, 0)) as piutang
FROM t
WHERE t.kdtrans = 'PJ';
```
